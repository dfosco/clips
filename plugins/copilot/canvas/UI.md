# Canvas UI source and build

The canvas is a React application, bundled by Vite with the Tailwind v4 Vite
plugin. It uses real shadcn/ui radix-nova components generated by the official
CLI (`search @shadcn`, `docs`, then `add @shadcn/...`) and maintained as source
under ui/components/ui. Initial CLI version is recorded with shipping evidence.
It is not a CSS imitation of shadcn. components.json and jsconfig.json locate
these components and the local cn helper.

Official references checked for this change:

- https://ui.shadcn.com/docs/installation/manual
- https://ui.shadcn.com/docs/installation/vite
- https://ui.shadcn.com/docs/components/radix/button (and the corresponding Card,
  Dialog, Field, Native Select, Toggle Group, Input, Textarea, Badge, Alert,
  Empty and Separator pages)
- https://tailwindcss.com/docs/installation/using-vite
- https://primer.style/octicons/code/

Local customization is explicit: Button has padded 40px controls and a 44px
wrapping record-title variant; Dialog has a padded surface and 40px dismissal;
Input/Native Select/Toggle targets are 40px. Components keep native button and
form semantics, focus-visible rings and disabled states. Radix supplies modal
focus management, Escape/outside dismissal and keyboard filter navigation.
No interactive card wraps another button. Primer Octicons replace all icon
imports; their currentColor SVGs come from @primer/octicons-react. The registry
CLI initially generated Lucide imports, which were replaced with Octicon
counterparts. Future registry additions must retain the Primer mappings.
Semantic theme tokens in ui/theme.css use GitHub/Primer light/dark surfaces,
GitHub green primary actions and blue focus rings, honoring Copilot host tokens.
There are no downloaded fonts or image icon substitutes.

From plugins/copilot:

    npm ci --include=dev --include=optional
    npm run build
    npm run check:build
    npm test

The maintained installer (`node scripts/install-copilot.js` from repository
root) verifies committed source/build hashes before exposing links, runs the
locked production dependency closure and verifies again through the installed
link. It does not need build tools at runtime. Rebuild and commit dist together
with changed UI sources. scripts/build-canvas.mjs produces a deterministic
manifest without timestamps. Repeating the same lock/source build must yield
identical asset hashes. The service snapshots verified index/assets at provider creation so old provider
code cannot serve a newer renderer against an old API. Installed diagnostics
report exact emitted asset identities; actual App logs are still needed to prove host activation.
